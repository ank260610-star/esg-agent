# 三人协作约定

## 分工

- 队长：需求、业务后端协调、指标/评分规则、申报材料。
- 智能体成员：Harness接入、插件、提示词、流程与双方联调。
- 资料成员：公开报告、人工标注、复核、错误清单和验证。

## 分支与PR

main保留可运行或明确标注的初始化状态。功能分支示例：feat/backend-evidence、feat/harness-tools、data/byd-gold。请勿三人直接在main同时提交。

每个小功能一个PR，写清变化、验证、接口影响、已知问题。接口修改同时更新contracts、示例和调用方；由另一端成员检查。没有跑真实模型时如实填写。

## 第一轮目标

1. 后端：提供可定位原文的search_evidence和候选校验。
2. 智能体：以模拟接口跑通调用，再切真实服务。
3. 资料：核对六项指标及脚注，提交参考数据。

共同验收：用户问一项指标，智能体调用真实服务，返回数值、单位、年份和有效原文页码。

## 文件与权限

不提交密钥、完整报告、候选人材料、本地数据库及原始日志。新成员由仓库所有者邀请，获得写权限即可；不要共享账号或密钥。不要覆盖其他人未提交修改。

## 目录映射

实现方案原src/esg_app统一映射到backend/src/esg_app；其余根目录tests、rules、contracts、harness-plugin不变。其余字段和验收要求沿用实施文档。
